# Task Service

Сервис для управления задачами с HTTP API на Go.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск через Docker Compose

```bash
docker compose up --build
```

После запуска сервис будет доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

Причина в том, что SQL-файл из `migrations/0001_create_tasks.up.sql` монтируется в `docker-entrypoint-initdb.d` и применяется только при инициализации пустого data volume.

## API

Базовый префикс API:

```text
/api/v1
```

Основные маршруты:

- `POST /api/v1/tasks`
- `GET /api/v1/tasks`
- `GET /api/v1/tasks/{id}`
- `PUT /api/v1/tasks/{id}`
- `DELETE /api/v1/tasks/{id}`

Новые маршруты для периодических задач:

- `POST /api/v1/task-templates` - Создать шаблон периодической задачи
- `GET /api/v1/task-templates` - Получить список шаблонов
- `GET /api/v1/task-templates/{id}` - Получить шаблон по ID
- `PUT /api/v1/task-templates/{id}` - Обновить шаблон
- `DELETE /api/v1/task-templates/{id}` - Удалить шаблон
- `POST /api/v1/task-templates/generate` - Ручной запуск генерации задач на определенную дату (для тестирования)
- `POST /api/v1/task-templates/{id}/generate` - Ручной запуск генерации задач для конкретного шаблона на N дней вперед

## Архитектурные решения

### 1. Разделение на Шаблоны и Экземпляры задач

Вместо генерации тысячи задач на несколько лет вперед сразу при создании правила, используется разделение:
- **TaskTemplate** - хранит правило периодичности, заголовок, описание
- **Task** - конкретная задача на определенный день, сгенерированная из шаблона

Преимущества:
- Меньше нагрузки на БД (не храним задачи на 10 лет вперед)
- Легко изменять правило в будущем (изменяем только шаблон, а не тысячи задач)
- Меньше вероятности рассинхронизации при изменении правил

### 2. Идемпотентность

Добавлен уникальный индекс `UNIQUE(template_id, scheduled_date)` в таблице tasks, который гарантирует, что для одного шаблона никогда не будет создано две одинаковые задачи на один день. Это защищает от дублирования даже если воркер запустится несколько раз подряд или сервер перезагрузится.

### 3. Фоновый воркер без поллинга

Вместо поллинга каждую минуту используется более эффективный подход:
- При создании/обновлении шаблона сразу генерируются задачи на 30 дней вперед
- Фоновая горутина просыпается ТОЛЬКО раз в сутки ровно в полночь UTC
- При пробуждении генерируются задачи на новый день по всем активным шаблонам

Итоговая нагрузка на БД: 1 запрос в сутки + запросы при создании/изменении шаблонов. Это на порядки эффективнее, чем поллинг каждую минуту.

### 4. Часовые пояса

Все вычисления дат происходят в UTC. В реальном проекте для медицинских приложений необходимо добавить поле timezone для клиники/врача и учитывать его при расчете начала дня.

### 5. Граничные случаи

Реализована обработка следующих граничных случаев:
- **31 число месяца**: Если запрошено создание задачи 31 числа, а в текущем месяце меньше дней, задача создается в последний день месяца
- **Четные/нечетные дни**: Корректная обработка для любых месяцев
- **Проверка дат**: Запрещено создание задач до даты начала действия шаблона и после даты окончания
- **Ручная генерация**: Добавлены эндпоинты для ручного запуска генерации задач, что позволяет легко тестировать систему без ожидания полночи

## Примеры запросов

Создание шаблона задачи на каждый второй день:
```json
POST /api/v1/task-templates
{
  "title": "Обход пациентов",
  "description": "Обойти всех пациентов отделения",
  "recurrence_type": "daily",
  "recurrence_params": {"interval": 2},
  "start_date": "2026-04-09"
}
```

Создание шаблона задачи на каждый 15 и 31 число месяца:
```json
POST /api/v1/task-templates
{
  "title": "Месячный отчет",
  "description": "Подготовить месячный отчет по работе отделения",
  "recurrence_type": "monthly",
  "recurrence_params": {"days": [15, 31]},
  "start_date": "2026-04-09"
}
```

Ручная генерация задач на определенную дату:
```json
POST /api/v1/task-templates/generate
{
  "date": "2026-04-10"
}
```
